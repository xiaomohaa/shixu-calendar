# Windows 悬浮提醒设计与验证

现有链路保持：Rust 的 30 秒后台 tick → 主 WebView 的 ICS Worker 计算事件和提醒时间 → notifyReminder → SQLite claim_reminder。仅扩展展示出口、操作路由和稍后提醒，不另建 ICS 计算器，不使用 Electron。

## 约定

- 默认仍为系统通知，设置可切换 macOS 风格悬浮通知，并可测试当前模式。
- 每条悬浮提醒为一个透明、无边框、置顶、跳过任务栏、不可聚焦的 Tauri WebviewWindow，按屏幕工作区右上角堆叠，最多同时三条，工作区过小时减少可见数量。
- 固定使用主显示器，主显示器暂不可读时退回首个可用显示器。窗口贴主显示器工作区右上边缘，卡片上下各保留4px、左右各8px逻辑阴影留白，原生窗口紧邻，卡片之间可见间距约8px；位置按物理像素计算，尺寸按主显示器 DPI 换算。维护循环重新读取主显示器、工作区和缩放，主屏切换时所有可见通知一起重新定位，处理显示器断开、任务栏及分辨率变化。
- 通知使用独立渲染入口，不启动主 App 或提醒调度。仅可调用自己窗口的通知专用命令，不能调用 shixu_call 读取或修改日历。
- 提醒仍使用 claim_reminder 去重。待显示通知及稍后提醒扩展存入同一 SQLite，已成功显示标记送达；队列未显示与尚未到期的稍后提醒在重启后继续处理。
- 通知按标题、正文和按钮的实际高度测量，窗口高度有上限，使用真实高度重新堆叠；内容完成测量后才显示，不保留固定高度空白。
- 悬浮展示约10秒，悬停暂停；进入/退出只动画 transform 与 opacity。Rust 负责到期和兜底释放，WebView 完成动画后确认关闭，避免视图崩溃留下置顶空窗。
- 稍后提醒默认为10分钟，不修改事件及其原始提醒。打开日程通过受验证的资源标识路由到主窗口，主界面尚未挂载时保留待打开操作。测试通知没有伪造的日程。
- 主窗口 CloseRequested 仍按 closeToTray 设置处理；其他窗口自然关闭并清理管理状态，不收纳主窗口、不退出应用。
- 系统通知继续使用已有插件，附带提醒关联信息；插件报告点击时打开对应日程，缺少关联信息时唤出主窗口。

## 验证

Rust 测试覆盖去重、持久队列、稍后提醒、失效资源、屏幕负坐标、工作区、DPI、堆叠容量与边界。前端验证主题、倒计时/悬停、动画、操作错误和日程路由。实际 Windows 测试检查不抢焦点、窗口堆叠/销毁、关闭行为、数据库持久化与现有后台提醒链路。最后执行 TypeScript 检查、Rust 测试及正式配置 Windows x64 构建。

原生验证使用 GetForegroundWindow、GetWindowRect、GetDpiForWindow 与 GetMonitorInfo 读取实际句柄、样式、DPI 和工作区；读取时启用每显示器 DPI 感知，避免坐标虚拟化。Tauri 的普通 show 在实测中仍会激活窗口，因此 Windows 分支改用 SW_SHOWNOACTIVATE。创建/显示/移动/销毁不持有通知状态锁，避免 UI 线程销毁回调与工作线程互相等待。

`npm run test:tauri-notification` 通过现有提醒调度触发真实测试日程，主窗口隐藏后仍会提醒；然后点击稍后提醒、检查数据库到期时间、退出并重新启动验证恢复。测试仅在隔离数据库中将已保存的到期时间提前，不在业务代码中添加“快速稍后提醒”分支。点击测试还覆盖事件改期后的新日期和未保存编辑确认。

当前 Windows 硬件只有一个显示器，实测 DPI 为192（200%）。多 DPI 100%/125%/150%/200%、负坐标、顶部任务栏工作区、小工作区、不同卡片高度与容量变化由 Rust 几何测试覆盖；真实多显示器插拔和混合缩放硬件验证仍需相应设备。

2.2.2 关闭/销毁回调移除卡片后，立即在线程外触发重新排布和队列补充，不等待2秒维护循环。可见窗口按220ms四次方减速曲线移动，布局有代次标识，后续布局变化从实际位置重新定向，取消旧动画，避免连续关闭时回跳。隐藏窗口直接定位，减少动态效果时直接补位。显示器、DPI或任务栏工作区变化时也直接安全定位，不播放穿越屏幕边界的移动动画。只在目标变化时启动动画，不持有状态锁调用原生窗口API。原生采样测试记录多个中间位置，验证500ms内补位、无逆向跳动；当前200% DPI硬件实测约245ms。
